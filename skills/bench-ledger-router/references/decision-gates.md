# Optional Jev and checkpoint gates

Jev is an independent signal, not an authority or proof. This integration is
unofficial. Do not imply endorsement or publish comparative Jev performance
without confirmed permission under applicable terms.

Call the configured adapter only when compact-state transmission is authorised
and can affect the choice. Otherwise use framework_only_local and
`Jev API call: not made`. Do not provision accounts/keys or make paid calls merely
because this skill was invoked. The existing Python adapter reads TYPESAFE_API_KEY
from its process environment; never expose or persist it. A process presence check
does not establish the environment of every desktop launcher.

Use separate typed finite choices for decomposition and each task. Include relevant
abstention choices; shortlist eligible triples. The optional CLI reserves one of
Jev's 255 choices for abstention, bounding its supplied catalogue to 254 combinations.
Validate response type, offered choice, confidence and probability distribution.
Preserve actual model/usage metadata. Deployment confidence thresholds are policy,
not measured accuracy bounds. Never raise one question's confidence using another's.

Use checkpoints when a gate before dependent work/external effects is useful,
not as mandatory overhead for every trivial step. Include goal, acceptance,
completed work, evidence, uncertainty, blockers and proposed next action; exclude
internal reasoning transcripts, credentials and raw conversations/videos.
The optional CLI gate asks independent next_action and risk_class choices and
releases only under the configured policy, continue and no_known_risk.
Local mode instead uses observable checks without inventing Jev answers/confidence.

When the session exposes the `jev` MCP server (`jev_route` tool, possibly with an
MCP prefix), it is the configured adapter in T3 Code: pass a stable `requestId`, the
compact task summary, the policy and the shortlisted model/effort candidates. A
repeated `requestId` with identical input returns the stored decision without a new
paid call. `insufficient-evidence` and other `isError` results mean
`Jev API call: made, no selection`; fall back to framework_only_local.
