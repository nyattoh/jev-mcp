# Task selection criteria

These are judgement criteria, not model rankings. Every target must be available
and representable by the executor. Do not infer prices or proven superiority from
brands or labels.

| Task | Primary constraints | Effort guidance |
| --- | --- | --- |
| File lookup/extraction/formatting | Read/tools, exact output, bounded scope | Lower supported setting for a straightforward acceptance check |
| External research | Live primary-source access and verification | Moderate; higher for contradictory or specialised evidence |
| Implementation | Writable actual checkout, code/test tools, interface context | Moderate for contained changes; higher for interacting constraints |
| Independent review | Concrete diff, source context, observable acceptance checks | Match ambiguity/blast radius; respect user's chosen reviewer |
| Scientific/quantitative synthesis | Assumptions, calculations, evidence and uncertainty | Higher for conflicting evidence; confidence is not proof |
| Integration | Combined behaviour and original goal | Usually parent-owned; higher for unresolved cross-task contradictions |

Compare serial_parent and parallel_disjoint. Parallelise independent research,
read-only reviews, or writers with disjoint ownership and known interfaces.
Related steps in one shared-state mutation are often better serial.

Estimate coordination/context/validation burden without claiming measured savings.
If a provider is unavailable, choose an authorised alternative and record why.
A user's mandatory but unavailable provider remains an unresolved decision;
do not silently substitute. There is no requirement to use every provider.

Effort labels do not provide cross-provider cost or quality rankings. A lowest
label does not establish adequate tools or quality. If the catalogue gives no
tool evidence, verify it separately or disclose the unverified dependency.
